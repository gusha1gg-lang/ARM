# ARM-OMK на Linux — установка и запуск

Инструкция для переноса комплекта `ARM-OMK-main` на Linux-сервер.
Проверено на Debian/Ubuntu-подобных системах (включая Astra Linux);
для RHEL/Alma/Rocky отличия указаны отдельно.

Код сайта, база и все ресурсы — кроссплатформенные: **переписывать ничего не
нужно**. Отличается только обвязка запуска: вместо `.bat` — shell-скрипты и
systemd, вместо `netsh` — `ufw`/`firewalld`.

Проверено на Ubuntu 26.04 (WSL2, systemd): Python 3.14, запуск вручную и
службой на порту 80, вход, 20 страниц, скачивание ярлыков, резервная копия,
таймер. Код также работает на Python 3.9–3.13.

---

## 0. Что лежит в папке `linux/`

| Файл | Назначение |
|---|---|
| `УСТАНОВКА.md` | эта инструкция |
| `start_server.sh` | запуск вручную (аналог `start_server.bat`) |
| `install_service.sh` | установка службы systemd + автозапуск (аналог `install_autostart.bat`) |
| `uninstall_service.sh` | удаление службы (аналог `remove_autostart.bat`) |
| `arm-omk.service` | шаблон юнита; пути подставляет установщик |
| `install_firewall.sh` | открыть порт в `ufw`/`firewalld` (аналог `install_firewall.bat`) |
| `backup_db.sh` | резервная копия базы (аналог `tools\backup_db.bat`) |
| `install_backup_timer.sh` | ежедневная копия по таймеру systemd |
| `arm-omk-backup.service`, `arm-omk-backup.timer` | шаблоны таймера |
| `nginx-arm-omk.conf.example` | вариант «nginx на 80 → сайт на 5000» |

Всё остальное (`app/`, `vendor/`, `instance/asutp.db`, `uploads/`, `serve.py`,
`tools/`, `docs/`) — общее с Windows-версией.

## 1. Требования

- Linux x64, systemd;
- Python **3.9+** (рекомендуется 3.11 или 3.12), пакет `python3`;
- права `root` (только для установки службы, порта 80 и брандмауэра);
- ~250 МБ на диске (комплект ~50 МБ + место под копии базы).

`pip` и интернет **не нужны**: все библиотеки лежат в `vendor/`.

```bash
python3 --version          # 3.9 и выше
```

Если Python нет:

```bash
# Debian / Ubuntu / Astra
sudo apt update && sudo apt install -y python3
# RHEL / Alma / Rocky
sudo dnf install -y python3
```

## 2. Перенос комплекта

Копируйте папку целиком — лучше `tar`/`rsync`, а не ZIP, собранный в Windows:
в ZIP имена с кириллицей могут перекодироваться, и часть файлов «потеряется».

**На Windows** (PowerShell, из `C:\ARM-OMK`):

```powershell
tar -czf arm-omk.tgz ARM-OMK-main
```

**На Linux**:

```bash
tar -xzf arm-omk.tgz -C /opt
sudo mv /opt/ARM-OMK-main /opt/arm-omk     # путь может быть любым
cd /opt/arm-omk
ls                                          # serve.py, vendor, linux, instance ...
```

Или напрямую:

```bash
rsync -a --info=progress2 user@windows-pc:/cygdrive/c/ARM-OMK/ARM-OMK-main/ /opt/arm-omk/
```

Сделайте скрипты исполняемыми (если права потерялись при копировании):

```bash
chmod +x linux/*.sh
```

## 3. Быстрая проверка (без установки службы)

Порт 80 в Linux привилегированный: обычный пользователь занять его не может.
Поэтому для пробы запускаем на 5000:

```bash
cd /opt/arm-omk
PORT=5000 ./linux/start_server.sh
```

Откройте `http://IP-сервера:5000/` — должна появиться страница входа.
Логин `admin`, пароль прежний (по умолчанию `11111111`).

Остановка — `Ctrl+C`. При первом запуске `serve.py` сам создаст `.env`
со случайным `SECRET_KEY` и папку `logs/`.

Проверка «жив ли сервер»:

```bash
curl -s http://127.0.0.1:5000/health     # {"status":"ok"}
```

> Если при старте написано «порт занят» — смотрите п. 11.

## 4. Установка службы (рекомендуется)

```bash
cd /opt/arm-omk
sudo ./linux/install_service.sh
```

Скрипт:

1. создаёт системного пользователя `arm-omk`;
2. даёт ему права на запись в `instance/`, `uploads/`, `logs/`, `_backup/`
   (код и `vendor/` остаются у root — служба их только читает);
3. подставляет реальные пути в `arm-omk.service` и кладёт его в
   `/etc/systemd/system/`;
4. включает автозапуск и запускает сайт.

Перед запуском скрипт проверяет, что служба действительно сможет войти в
каталог проекта: если комплект лежит в `/root` или в домашней папке с правами
`750`, установка остановится с понятным сообщением (перенесите проект в `/opt`).

Порт 80 служба получает через `CAP_NET_BIND_SERVICE` — **root-права самой
службе не нужны**.

Управление:

```bash
systemctl status arm-omk --no-pager     # состояние
journalctl -u arm-omk -f                # журнал в реальном времени
sudo systemctl restart arm-omk          # перезапуск
sudo systemctl stop arm-omk             # остановка
```

Сайт: `http://IP-сервера/` — **без порта**.

## 5. Если порт 80 уже занят (nginx/apache)

Есть два варианта.

**Вариант A. Отдать 80 сайту ARM-OMK.** Остановить/удалить чужой веб-сервер,
затем п. 4.

**Вариант B. Оставить nginx на 80 и проксировать на ARM-OMK.**

```bash
# 1) сайт слушает только локальный порт
cd /opt/arm-omk
sed -i 's/^HOST=.*/HOST=127.0.0.1/; s/^PORT=.*/PORT=5000/' .env
sudo systemctl restart arm-omk

# 2) nginx проксирует 80 -> 5000
sudo cp linux/nginx-arm-omk.conf.example /etc/nginx/sites-available/arm-omk.conf
sudo ln -s /etc/nginx/sites-available/arm-omk.conf /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx
```

Для RHEL/Alma конфиг кладут в `/etc/nginx/conf.d/arm-omk.conf`.

## 6. Брандмауэр

```bash
sudo ./linux/install_firewall.sh
```

Скрипт сам определит `ufw` (Debian/Ubuntu/Astra) или `firewalld`
(RHEL/Alma/Rocky) и откроет порт из `.env` (по умолчанию 80).

Вручную:

```bash
sudo ufw allow 80/tcp && sudo ufw enable          # ufw
sudo firewall-cmd --permanent --add-service=http   # firewalld
sudo firewall-cmd --reload
```

Проверка с другого компьютера: `http://IP-сервера/`.

## 7. Резервные копии

Разовая копия:

```bash
./linux/backup_db.sh                 # только база
./linux/backup_db.sh --with-files    # база + uploads/ + Slegenie/
```

Копии кладутся в `_backup/db/`, хранятся последние 30 (меняется в `backup_db.sh`,
переменная `KEEP`). Копирование безопасно при работающем сайте — используется
SQLite backup API, журнал WAL учитывается.

Ежедневно в 03:00 (таймер systemd):

```bash
sudo ./linux/install_backup_timer.sh
```

Проверка:

```bash
systemctl list-timers arm-omk-backup.timer --no-pager
journalctl -u arm-omk-backup -n 20
ls -lh _backup/db/
```

## 8. Права и куда пишется информация

| Путь | Кто владеет | Что там |
|---|---|---|
| `app/`, `vendor/`, `linux/`, `docs/` | root, только чтение | код и библиотеки |
| `instance/asutp.db` | `arm-omk` | рабочая база (WAL, `-wal`/`-shm`) |
| `uploads/` | `arm-omk` | картинки камер |
| `logs/app.log` | `arm-omk` | журнал приложения |
| `_backup/` | `arm-omk` | резервные копии |
| `.env` | создаёт служба при первом старте | `SECRET_KEY`, `HOST`, `PORT` |

Проверить и поправить права вручную:

```bash
sudo chown -R arm-omk:arm-omk /opt/arm-omk/{instance,uploads,logs,_backup}
sudo chgrp arm-omk /opt/arm-omk && sudo chmod g+w /opt/arm-omk
```

## 9. Отличия от Windows-версии

| Windows | Linux |
|---|---|
| `start_server.bat` | `linux/start_server.sh` |
| `install_autostart.bat` (Планировщик) | `linux/install_service.sh` (systemd) |
| `remove_autostart.bat` | `linux/uninstall_service.sh` |
| `install_firewall.bat` (`netsh`) | `linux/install_firewall.sh` (`ufw`/`firewalld`) |
| `tools\backup_db.bat` | `linux/backup_db.sh` + таймер systemd |
| порт 80 без прав администратора | порт 80 требует `CAP_NET_BIND_SERVICE` (уже в юните) |
| `.bat` в кодировке cp866 | `.sh` в UTF-8 с переводами строк LF |
| `vendor\*.pyd`, `vendor\bin\*.exe` | не используются; нужные части библиотек — чистый Python |
| ярлыки `.lnk` открываются | `.lnk` только скачиваются (см. п. 13) |
| миграция из Access через ODBC | только на Windows (см. п. 13) |

## 11. Частые проблемы

| Симптом | Причина | Решение |
|---|---|---|
| `bash: ./install_service.sh: /usr/bin/env: bad interpreter: No such file or directory` или `^M` | файл с переводами строк CRLF (правили в Блокноте) | `sed -i 's/\r$//' linux/*.sh` |
| Служба не стартует: `Changing to the requested working directory failed: Permission denied` | проект лежит в `/root` или домашней папке с правами `750` — служебный пользователь не может войти в каталог | перенести в `/opt`: `sudo mv <папка> /opt/arm-omk`, затем установить службу оттуда |
| `Permission denied` при старте на порту 80 | порт 80 привилегированный | запускать через службу (`install_service.sh`) или `sudo`, либо `PORT=5000` |
| `ОШИБКА: порт 80 уже занят` | nginx/apache/другой сайт | остановить чужой сервер или перейти на схему с nginx (п. 5) |
| `Не найден каталог vendor/` | скопировали не всю папку | перекопировать комплект целиком |
| 404 на картинку камеры | регистр имени файла (`Cam02.jpg` ≠ `CAM02.JPG`) | на Linux регистр важен: переименуйте файл в `uploads/Cam02.jpg` |
| Кириллические имена превратились в `?`/кракозябры | копирование ZIP-архивом из Windows | перекопировать через `tar`/`rsync`, проверить `ls Slegenie` |
| `.env` не создаётся в `/opt/arm-omk` | нет прав на запись в каталог | `sudo chgrp arm-omk /opt/arm-omk && sudo chmod g+w /opt/arm-omk` |
| Служба падает, в журнале `AVC denied` (Astra/RHEL) | SELinux | `sudo ausearch -m avc -ts recent`; при необходимости `sudo chcon -R -t usr_t /opt/arm-omk` |
| Сайт открывается, но без стилей | не скопированы `app/static/` | перекопировать `app/` целиком |

Журналы: `journalctl -u arm-omk -n 50`, `logs/app.log`.

## 12. Обновление и удаление

**Обновление** (новая версия комплекта):

```bash
sudo systemctl stop arm-omk
sudo cp -a /opt/arm-omk /opt/arm-omk.bak      # страховка
# заменить app/, vendor/, tools/, docs/, serve.py; БД и uploads не трогать
sudo systemctl start arm-omk
```

Либо распаковать новый комплект рядом, перенести в него `instance/`, `uploads/`,
`.env` и переключить юнит на новый путь (`install_service.sh` в новой папке).

**Удаление службы** (данные сохраняются):

```bash
sudo ./linux/uninstall_service.sh
```

## 13. Что на Linux работает иначе (не блокеры)

| Что | Поведение |
|---|---|
| **Ярлыки `.lnk`** (раздел «Все ярлыки») | скачиваются как файлы, но «ярлыками Windows» не являются. Раздел остаётся архивом; при желании замените на `.desktop` или обычные ссылки |
| **Миграция из MS Access** (`scripts/migrate_access_to_sqlite.py`, `tools/verify_db.py`) | требует ODBC-драйвер Access и работает только на Windows. База уже перенесена — на Linux эти шаги не нужны. Сверку с `.mdb` при необходимости делайте на Windows |
| **`vendor/*.pyd`, `vendor/bin/*.exe`** | Windows-бинарники, на Linux не используются и не мешают (сайт их не импортирует) |
| **`python-dotenv` / `waitress` / Flask** | чистый Python, работают как есть |
| **`tools/check_dist.py`** | работает (только `sqlite3`), но проверяет Windows-комплект (`.bat`, cp866) — на Linux часть проверок неприменима |
