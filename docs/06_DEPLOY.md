# Этап 6. Перенос на сервер и запуск

Инструкция для случая: **Windows 11, доменная машина, есть интернет, но
`pip install` запрещён политикой ИБ**. Все библиотеки уже лежат внутри проекта,
устанавливать на сервере ничего не нужно. Исключение — ODBC-драйвер Access,
и только если миграцию базы вы делаете на сервере (п. 4.2).

Проверено на: Python 3.13.0 и 3.12.10 (x64), Windows 11.

---

## 1. Что копировать на сервер

Копируется **папка проекта целиком**, кроме перечисленного в п. 2.

| Копировать | Зачем |
|---|---|
| `app\` | само приложение (шаблоны, CSS, код) |
| `vendor\` | Flask, Jinja2, Werkzeug, dotenv, waitress, pyodbc — **без них не запустится** |
| `instance\asutp.db` | рабочая база (в git её нет — копируется отдельно!) |
| `uploads\` | 82 картинки камер; в БД лежат пути `uploads/<файл>` |
| `Slegenie\` | 32 файла ярлыков для раздела «Все ярлыки» |
| `img\`, `css\`, `images\` | оформление и картинки legacy-сайта |
| `*.files\` (папки) | картинки внутри инструкций `.htm` |
| `*.htm` в корне | страницы «Настройки», «Инструкция по перезапуску WinCC» и т. п. |
| `serve.py`, `start_server.bat` | рабочий запуск |
| `install_autostart.bat`, `remove_autostart.bat` | автозапуск |
| `requirements.txt`, `.env.example` | для справки / восстановления |

Если базу нужно пересоздать из Access **на сервере**, дополнительно
скопируйте `App_Data\AsutpDB.mdb`, `scripts\` и `tools\verify_db.py` — см. п. 4.

## 2. Что копировать **не нужно**

| Не нужно | Почему |
|---|---|
| `tools\` (кроме `verify_db.py`) | тесты и сверки, нужны только при разработке |
| `scripts\` | нужны только при миграции на сервере (п. 4) |
| `_backup\` | старые копии (свои копии сервер будет делать сам) |
| `*.aspx`, `*.cs`, `App_Code\` | исходный legacy-сайт, для работы не используется |
| `App_Data\AsutpDB.mdb` | исходная база Access; нужна только при миграции на сервере (п. 4) |
| `venv\` | виртуальное окружение разработчика |

Итого проект занимает ~51 МБ, из них 5,4 МБ — `vendor\`.

## 3. Требование к Python

Подходит **Python 3.12 или 3.13, обязательно x64** (проверено на 3.13.0 и
3.12.10). Версия должна быть в `PATH` или ставиться лаунчером `py`.

Почему так:

| Модуль в `vendor\` | 3.13 | 3.12 |
|---|---|---|
| Flask, Jinja2, Werkzeug, dotenv, waitress, click, itsdangerous, blinker | чистый Python | чистый Python |
| `markupsafe` | ускоренный `_speedups.cp313-win_amd64.pyd` | `.pyd` не подходит, автоматически берётся чистый Python — работает так же, чуть медленнее |
| `pyodbc` (только для миграции) | `pyodbc.cp313-win_amd64.pyd` | `pyodbc.cp312-win_amd64.pyd` — лежит рядом |

Обе сборки `pyodbc` лежат в одной папке, нужная подхватывается по версии
Python. Ничего устанавливать не нужно.

Проверка на сервере:

```powershell
python --version      # Python 3.12.x или 3.13.x
python -c "import sys; print(sys.maxsize > 2**32)"   # True (64-bit)
```

Если на сервере **другая** версия Python (3.11, 3.14 и т. п.), на машине
с интернетом (или где pip разрешён) выполните той же версией Python, что
стоит на сервере:

```powershell
pip install --target C:\ARM-OMK\vendor --upgrade -r requirements-dev.txt
```

и скопируйте `vendor\` заново.

## 4. Перенос базы из Access на сервере (необязательно)

Базу можно перенести двумя способами — результат одинаковый, SQLite-база это
один файл `instance\asutp.db`:

* **A. На ПК, где `pip` разрешён** — выполнить миграцию у себя и скопировать
  готовый `instance\asutp.db` на сервер (см. п. 1). Проще, ничего ставить
  на сервер не нужно.
* **B. На сервере** — если миграцию нужно делать именно там (например,
  `AsutpDB.mdb` обновляется и живёт на сервере). Порядок ниже.

### 4.1. Что дополнительно скопировать

| Копировать | Зачем |
|---|---|
| `App_Data\AsutpDB.mdb` | исходная база Access (1,7 МБ) |
| `scripts\` | `schema.sql` + `migrate_access_to_sqlite.py` + `migrate_legacy_admin.py` |
| `tools\verify_db.py` | сверка Access ↔ SQLite |

`pyodbc` уже лежит в `vendor\` и подхватывается скриптами автоматически —
`pip install` на сервере **не нужен**.

### 4.2. Требование: ODBC-драйвер Access

Проверить, установлен ли драйвер (PowerShell):

```powershell
Get-OdbcDriver | Where-Object { $_.Name -like "*Access*" }
```

Должна быть строка `Microsoft Access Driver (*.mdb, *.accdb)`. Если её нет —
установите **Microsoft Access Database Engine 2016 Redistributable
(`AccessDatabaseEngine_X64.exe`)** с сайта Microsoft (нужны права
администратора). Разрядность драйвера должна совпадать с Python:
64-бит Python → 64-бит драйвер.

### 4.3. Порядок

1. Остановить сайт (`Ctrl+C` в окне `start_server.bat`).
2. Сделать страховочную копию текущей базы (`instance\asutp_before_migration.db`):

   ```powershell
   cd C:\ARM-OMK
   Copy-Item instance\asutp.db instance\asutp_before_migration.db
   ```

3. Пересоздать базу из Access:

   ```powershell
   python scripts\migrate_access_to_sqlite.py
   ```

   Ожидаемо: список из 14 таблиц с количеством строк, затем
   `Итого строк: 3880` и `Миграция завершена успешно`.

   **Внимание:** скрипт **удаляет** `instance\asutp.db` и создаёт его заново.
   Всё, что было введено через сайт, пропадёт (в Access этих данных нет).

4. Перенести администратора из legacy-таблицы `UserPass`:

   ```powershell
   python scripts\migrate_legacy_admin.py
   ```

   Скрипт идемпотентен: повторный запуск дубликатов не создаёт.

5. Сверить перенос:

   ```powershell
   python tools\verify_db.py
   ```

   Ожидаемо: `Access=3880, SQLite=3880`, «Внешние ключи: OK»,
   «Кириллица: OK». Отчёт перезаписывается в `docs\02_DB.md` — это нормально.

6. Запустить `start_server.bat`, войти (`admin` + прежний пароль),
   сразу сменить пароль (см. п. 5).

Вернуть прежнюю базу, если что-то пошло не так:

```powershell
Copy-Item instance\asutp_before_migration.db instance\asutp.db -Force
Remove-Item instance\asutp.db-wal, instance\asutp.db-shm -ErrorAction SilentlyContinue
```

### 4.4. Ошибки при миграции

| Ошибка | Причина / решение |
|---|---|
| `ModuleNotFoundError: No module named 'pyodbc'` | запущен другой Python (не 3.12/3.13 x64) или в `vendor\` нет файла `pyodbc.cp312/313-win_amd64.pyd` |
| `pyodbc.InterfaceError: Data source name not found` | не установлен ODBC-драйвер Access (п. 4.2) |
| `architecture mismatch` / «драйвер не найден» | 32-бит драйвер при 64-бит Python (или наоборот) |
| `Could not lock file` / рядом появился `.ldb` | `.mdb` открыт в MS Access — закройте его |
| `no such table: users` | не выполнен шаг 4 (`migrate_legacy_admin.py`) |
| `checksum=FAIL` у `IPaddress4` / `IPaddress5` в `verify_db.py` | это **реальные правки**, сделанные через сайт после миграции (IDPC 689, 138, 435), а не ошибка переноса |

## 5. Первый запуск

1. Скопируйте папку, например в `C:\ARM-OMK`.
2. Дважды щёлкните `start_server.bat` (или `python serve.py`).

При первом запуске `serve.py`:

* создаёт `.env` (если его нет);
* генерирует случайный `SECRET_KEY` и записывает его в `.env`;
* включает WAL для базы;
* создаёт `logs\` и начинает писать `logs\app.log`.

В окне будет примерно:

```
ARM-OMK — Справочник ТЭСК ТБД
  адрес:  http://0.0.0.0:5000/
  БД:     C:\ARM-OMK\instance\asutp.db
  журнал: C:\ARM-OMK\logs\app.log
  остановка: Ctrl+C
```

3. На сервере откройте <http://127.0.0.1:5000/> — должен открыться вход.
4. Войдите (`admin` и прежний пароль), сразу смените пароль:
   шапка → **«Сменить пароль»**.

### Настройки в `.env`

Файл создаётся автоматически; менять нужно только при необходимости:

| Переменная | Значение на сервере | Комментарий |
|---|---|---|
| `SECRET_KEY` | сгенерирован | не менять без причины: все сессии сбросятся |
| `DATABASE_PATH` | `instance/asutp.db` | относительно корня проекта |
| `UPLOAD_FOLDER` | `uploads` | должно совпадать с путями в БД |
| `HOST` | `0.0.0.0` | доступ из локальной сети |
| `PORT` | `5000` | при смене — поправить правило брандмауэра |
| `DEBUG` | `0` | на сервере всегда 0 |
| `LOG_DIR` | `logs` | журнал приложения |

## 6. Доступ из локальной сети и брандмауэр

Если `HOST=0.0.0.0`, сайт слушает все интерфейсы. Нужно разрешить порт
в брандмауэре Windows (PowerShell **от имени администратора**):

```powershell
New-NetFirewallRule -DisplayName "ARM-OMK web" -Direction Inbound `
  -Protocol TCP -LocalPort 5000 -Action Allow -Profile Domain,Private
```

С другого ПК: `http://<IP-сервера>:5000/` (IP узнать: `ipconfig`).

Открывать наружу (за пределы локальной сети) не нужно и не рекомендуется:
HTTPS и защита от подбора пароля не настраивались.

## 7. Автозапуск

### Вариант A — при входе пользователя (проще, работает всегда)

1. Правый клик на `install_autostart.bat` → **«Запуск от имени администратора»**.
2. Скрипт создаёт задание `ARM-OMK`: запуск `start_server.bat` при входе
   пользователя в Windows (с задержкой 30 с).
3. Проверить: `schtasks /Query /TN "ARM-OMK"`.
4. Удалить: `remove_autostart.bat` или `schtasks /Delete /TN "ARM-OMK" /F`.

Требование: пользователь должен входить в систему (машина доменная — вход
есть), либо включён автоматический вход. Окно сервера остаётся свёрнутым —
закрывать его нельзя.

### Вариант B — служба при загрузке ПК, без входа пользователя

Нужно, чтобы Python был установлен **для всех пользователей** (обычно
`C:\Program Files\Python313`), иначе задача от `SYSTEM` не найдёт `python`.
Тогда создайте задание вручную или так (администратор):

```powershell
schtasks /Create /TN "ARM-OMK" /SC ONSTART /RU SYSTEM /RL HIGHEST `
  /TR "C:\ARM-OMK\start_server.bat" /F
```

Проверка после перезагрузки: `schtasks /Query /TN "ARM-OMK"` и
<http://127.0.0.1:5000/health> → `{"status":"ok"}`.

### Чего не делаем

NSSM и другие сторонние `.exe` не используются: их нужно скачивать, а на
сервере это может быть запрещено. Планировщик заданий Windows решает задачу
без загрузок.

## 8. Резервные копии

Копия БД делается через `sqlite3 backup API` — она корректна и при включённом
WAL (обычное копирование файла в этот момент может дать «битую» базу).

```powershell
python tools\backup_db.py               # только БД
python tools\backup_db.py --with-files  # + uploads\ и Slegenie\
python tools\backup_db.py --keep 60     # хранить 60 последних копий
tools\backup_db.bat                     # то же для планировщика
```

Куда: `_backup\db\asutp-ГГГГММДД-ЧЧММСС.db` (и `_backup\files\<метка>\`).

### Ежедневное расписание (Планировщик заданий)

1. «Планировщик заданий» → «Создать задачу».
2. Имя: `ARM-OMK backup`.
3. «Триггеры» → «Ежедневно», время (например, 18:00).
4. «Действия» → «Запуск программы»:
   * программа: `C:\ARM-OMK\tools\backup_db.bat`
   * рабочий каталог: `C:\ARM-OMK`
5. «Условия» → снять «Выполнять только при питании от сети» (по желанию).
6. Проверить: правый клик по заданию → «Выполнить», затем посмотреть
   `_backup\logs\backup.log`.

Для копии на другой диск/сетевую папку добавьте второе действие
`robocopy C:\ARM-OMK\_backup \\nas\share\ARM-OMK_backup /MIR` (или копируйте
вручную). Помните: в `_backup` попадает и `UserPass.Pass` (см. п. 11).

### Восстановление

1. Остановить сервер (`Ctrl+C` в окне, либо завершить процесс `python`).
2. Скопировать нужную копию на место рабочей базы:

```powershell
Copy-Item "_backup\db\asutp-20261028-180000.db" "instance\asutp.db" -Force
Remove-Item "instance\asutp.db-wal","instance\asutp.db-shm" -ErrorAction SilentlyContinue
```

3. Запустить `start_server.bat`, проверить `/health` и раздел «Логи».

## 9. Журналы и диагностика

| Что | Где |
|---|---|
| Ошибки приложения | `logs\app.log` (ротация: 1 МБ × 5 файлов) |
| Ошибки планировщика/запуска | окно `start_server.bat` |
| Журнал бэкапов | `_backup\logs\backup.log` |
| Действия пользователей | страница «Логи» (`/Logs.aspx`) |
| Проверка «жив ли» | `http://127.0.0.1:5000/health` |

Если сайт не открывается:

1. `netstat -ano | findstr :5000` — слушает ли порт;
2. `logs\app.log` — есть ли traceback;
3. права на запись в `C:\ARM-OMK` (БД, `logs`, `uploads`) у того пользователя,
   под которым запущен сервер.

## 10. Обновление проекта и откат

Обновление:

1. Сделать копию: `tools\backup_db.bat`.
2. Остановить сервер.
3. Заменить папку `app\` (и при необходимости `vendor\`), **не трогая**
   `instance\`, `uploads\`, `.env`, `logs\`.
4. Запустить `start_server.bat`, открыть сайт, проверить `/health`.

Откат:

1. Остановить сервер.
2. Вернуть прежнюю папку `app\`.
3. При необходимости восстановить БД из `_backup\db\` (см. п. 8).

## 11. Необязательно: затереть `UserPass.Pass`

Legacy-таблица `UserPass` перенесена 1-в-1, и в поле `Pass` лежит **пароль
администратора в открытом виде** (такой же, как в старой Access-базе).
Структуру и данные по правилам миграции не меняли.

Пароль в рабочей таблице `users` хранится правильно (PBKDF2-SHA256), поэтому
`UserPass` для входа **не используется**. Если не хотите, чтобы открытый
пароль попадал в копии базы, выполните в PowerShell (сервер остановлен):

```powershell
@'
import sqlite3
c = sqlite3.connect(r"C:\ARM-OMK\instance\asutp.db")
c.execute('UPDATE "UserPass" SET "Pass" = NULL')
c.commit()
print("изменено строк:", c.total_changes)
'@ | python -
```

(конструкция `@' ... '@ | python -` — это передача скрипта в Python без
создания файла; кавычки внутри не экранируются).

После этого старый пароль останется только в резервных копиях, сделанных
до изменения. Выполнять **только после того, как вход под `admin` проверен**
и новый пароль сохранён.
