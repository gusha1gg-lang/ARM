# КОНТЕКСТ

Пользователь имеет legacy-сайт на ASP.NET (C#) с базой данных MS Access. Сайт работает локально на его ПК (Windows 11, личное использование, без требований к публичной безопасности).

Цель — полностью переписать проект:
- Бэкенд: Python (рекомендуй Flask или FastAPI, обоснуй выбор для слабой бесплатной модели и простоты поддержки).
- БД: SQLite (заменить MS Access). **Структура таблиц и все данные должны перенестись без изменений**: те же таблицы, те же поля (имена, типы — с маппингом Access→SQLite, но без переименований и без потери данных), те же связи. Допускается только технически необходимое преобразование типов (например, `AutoNumber`→`INTEGER PRIMARY KEY AUTOINCREMENT`, `DateTime`→`TEXT/DATETIME`) с фиксацией в логе. Никаких удалений строк, полей или таблиц, никакой «нормализации» и переименований без явного согласования.
- Фронтенд: сохранить текущую структуру страниц и навигацию. Визуально — аккуратно улучшить (современные CSS, адаптивность, читаемость), но НЕ менять расположение блоков, названия разделов и логику работы без явного согласования.
- Новые функции: многопользовательский режим (вместо одного админа) + роли: `viewer` (просмотр), `editor` (редактирование), `admin` (полный доступ, управление пользователями и ролями).
- Документация: вести журнал всех изменений по этапам.

# ЗАДАЧА

Выполни миграцию проекта поэтапно. Для каждого этапа: выполни работу, самопроверь результат, запиши отчёт в документацию, дождись подтверждения пользователя перед переходом дальше.

# ПРИНЦИПЫ РАБОТЫ

1. **Диагностика до кода.** Сначала изучай, потом меняй.
2. **Ничего не удаляй безвозвратно.** Перед изменениями создавай резервные копии (`_backup/` с датой), оригинал не трогай.
3. **Один этап = один проверяемый результат.** Не смешивай этапы.
4. **Документируй каждое изменение.** Файл `MIGRATION_LOG.md` в корне проекта.
5. **Сохраняй поведение.** Любое отклонение от оригинала (в т.ч. улучшение визуала) фиксируй в логе с обоснованием.
6. **Самопроверка обязательна.** После каждого этапа — чек-лист и запуск проекта.
7. **Данные и структура БД — неприкосновенны.** Перенос таблиц и строк выполняется 1-в-1. Любое изменение схемы (даже вынужденное, из-за несовместимости типов) фиксируется в `MIGRATION_LOG.md` с указанием «было → стало → почему».

# ЭТАПЫ РАБОТЫ

## Этап 0. Аудит исходного проекта (без изменений)
- Просканируй директорию проекта: найди `.aspx`, `.cs`, `.cshtml`, `.config`, `.mdb`/`.accdb`, статические ресурсы (CSS/JS/изображения).
- Составь инвентаризацию: список страниц, их назначение, навигация, формы, таблицы БД (структура из Access: таблицы, поля, типы, связи), текущая аутентификация, места хранения данных.
- Определи точки, где логика завязана на Access-специфику (SQL-синтаксис, OleDb, типы данных).
- Выведи отчёт в `docs/00_AUDIT.md` в формате Markdown (таблицы + списки).
- **Стоп.** Покажи отчёт пользователю и дождись подтверждения.

## Этап 1. План миграции и архитектура
- На основе аудита составь план: карта страниц (старая → новая), схема SQLite (DDL), стратегия миграции данных из Access в SQLite (через `pyodbc`/`pandas`/CSV-промежуток), схема аутентификации и ролей.
- Обоснуй выбор фреймворка (Flask/FastAPI) и структуру папок проекта.
- Выведи `docs/01_PLAN.md` со схемой БД (SQL DDL в XML-блоке), картой страниц и порядком работ.
- **Стоп.** Дождись подтверждения.

## Этап 2. Каркас проекта и БД
- Создай структуру Python-проекта, `requirements.txt`, конфиг.
- Реализуй схему SQLite (DDL), **точно повторяющую структуру таблиц Access** (имена таблиц/полей, типы с маппингом, первичные/внешние ключи).
- Реализуй скрипт миграции данных из Access в SQLite.
- Выполни миграцию и **докажи неизменность данных**:
  - сверка количества строк по каждой таблице (Access → SQLite): должно совпадать;
  - сверка контрольных сумм/выборочных строк (не менее 5 случайных строк на таблицу, включая граничные случаи: пустые поля, даты, спецсимволы, кириллица);
  - проверка сохранности связей (внешние ключи);
  - проверка кодировки (UTF-8, корректность кириллицы).
- Любое расхождение — блокер: остановись, опиши проблему, дождись решения пользователя.
- Отчёт в `docs/02_DB.md` с таблицей сверки: `таблица | строк в Access | строк в SQLite | статус ✅/❌` и списком любых изменений схемы.
- **Стоп.**

## Этап 3. Аутентификация, пользователи, роли
- Реализуй: регистрацию/создание пользователей админом, хеширование паролей (PBKDF2/werkzeug), вход/выход, сессии.
- Реализуй RBAC: роли `viewer` / `editor` / `admin`, декораторы проверки прав на маршрутах.
- Мигрируй существующего админа в новую таблицу `users` с ролью `admin`.
- Отчёт в `docs/03_AUTH.md` + инструкция «как добавить пользователя и назначить роль».
- **Стоп.**

## Этап 4. Перенос страниц и функционала (по одной странице)
- Для каждой страницы из карты: перенеси логику 1-в-1, сохрани URL/навигацию (по возможности), подключи проверку прав.
- Визуал: сохрани структуру, аккуратно обнови CSS (единый стиль, читаемость, адаптивность). Каждое визуальное отклонение — в лог.
- После каждой страницы — самопроверка (открыть, протестировать CRUD, проверить роли).
- Отчёт по странице в `docs/04_PAGES.md`.
- **Стоп** после каждых 1–2 страниц (или по запросу пользователя).

## Этап 5. Финальная проверка и документация
- Прогон всех страниц под каждой ролью (viewer/editor/admin).
- Проверка миграции данных, сверка.
- Повторная финальная сверка БД: количество строк и контрольные выборки по всем таблицам совпадают с оригиналом Access (или все отклонения задокументированы и согласованы).
- Итоговый `README.md`: запуск на Windows 11, зависимости, структура, роли, как добавить пользователя.
- Итоговый `MIGRATION_LOG.md`: сводка всех этапов и отклонений.
- **Стоп.** Финальное подтверждение.
